66 scenes · native 2048² · 4,224 tiles of 256² · 3,379 train / 845 test · 50 epochs · batch 32 · Adam · 3 classes · random_state=0

1. Executive summary

This is the first reproduction on the authors' own data. They supplied the source scenes directly — 66 PNGs, natively 2048×2048 — so the paper's full 66 × 64 = 4,224 tiles are reproduced exactly, with no resampling at any stage. The U-Net-Auto pipeline reaches 96.69% on original imagery (paper 90.18%, +6.51 pt) and 99.97% on thin-cloud/shadow filtered (paper 98.97%, +1.00 pt). Cloud-stratified: orig 95.31% / 97.62% high/low cloud, filtered 99.95% / 99.98%, with all 845 test tiles stratified and none dropped.

Two things to take from this, in order of importance.

  1. Our margin over the paper is a labeling artifact, not an improvement. Both branches are scored against auto-labels derived from the same tiles the U-Net consumes, so input and target are self-consistent by construction; the paper's pipeline does not have that property. Every Δ in this report carries that caveat. The filtered branch sits near ceiling for the same reason, amplified — see §3.
  2. The dataset change barely moved the numbers. An earlier run on a 63-scene Google Earth Engine export resized 2000→2048 scored 96.25% / 99.76% — within a point of this run. That retires the concern that the older results were an artifact of an incomplete, resampled export, and validates the --scene-size 0 path.

What reproduces cleanly is the paper's qualitative claim: thin-cloud/shadow filtering lifts every class to near-ceiling accuracy. What does not reproduce is the magnitude of that lift (+3.28 pt for us vs +8.79 pt for the paper), simply because our unfiltered baseline starts far higher and has less room to gain.

3. Why filtered-label consistency matters

Historical experiment (runs 0008 → 0009) that established the --filtered-labels default. Kept because it explains the near-ceiling filtered numbers in §2.

Retained as the evidence behind the --filtered-labels flag, measured on an earlier run: filtered inputs paired with raw-scene labels score ~90%, while self-consistent filtered labels score ~99.8%. This is the mechanism behind the near-ceiling filtered numbers in §2 — the default (filtered) makes input and target self-consistent; raw is the honest cross-comparison.

The workflow generator (workflow_generator.py) was extended with an --filtered-labels {filtered,raw} option (default filtered, "Option A"):

5. Conclusions

  • The paper's pipeline reproduces on its own data: both branches train cleanly, and filtering lifts every class to near-ceiling exactly as the paper claims.
  • Our absolute numbers exceed the paper's by 6.51 pt (orig) and 1.00 pt (filtered), but this reflects self-consistent auto-labeling, not a better model. Treated as a reproduction of the method rather than a benchmark, the result is a match.
  • The dataset question is closed. 66 native-2048² scenes, 4,224 tiles, no resampling — and the numbers barely moved from the older 63-scene resampled export, so that export was not distorting the earlier results.
  • Still open: the U-Net-Man column (needs manual labels), SSIM against manual labels, the Horovod scaling sweep, and a per-tile-filter variant re-run on this dataset.

6. Recommended next steps

  • Seeded / repeated runs — training is unseeded beyond the split, historically ~1 pt of run-to-run noise. Repeat the paper-default run a few times and report mean ± spread before publishing any sub-point comparison.
  • Per-tile filter variant on this dataset — --filter-scale tile was previously measured only on the legacy 63-scene export, so that comparison no longer has a matching baseline.
  • U-Net-Man baseline — the only route to the paper's other column; requires a manually-labeled validation set the authors have not released.
